### Decisions & gotchas carried forward
- **Adam's standing rules:**
  - don't change what he types (syntax, shortcuts) without asking;
  - full autonomy elsewhere;
  - report honestly what was and wasn't verified.
- **Drivers pin the light theme** (phase 2). A suite that wants dark sets
  `data-theme` itself. Without the pin, this dark-mode machine fails
  suites 12, 94 and 96.
- **Phase 2 structure lanes build on:**
  - `#root` has 20px side padding, and rows, heads and header go full
    bleed with `margin: 0 -20px`;
  - row columns are `--row-cols`;
  - the header is sticky, with the rundown strip inside it;
  - condensing sheds the ruler (suite 61 knows this);
  - the header's Save button draws its status from `data-status`.
- **Phase 2 deviations Adam may ask about:**
  - the b-roll label in the script shows the typed keyword ("B-roll:"),
    because it is document text, with no hanging indent (a cell's lines
    aren't blocks);
  - the row menu has no shortcut chips; the shortcuts are in each item's
    title;
  - status still cycles on click (the brief said keep behaviour), so the
    lamp button has no chevron.
- **Open for Adam (not blockers; lanes use the recommendations above):**
  - the start page's rundown for a recent script (read the file or not);
  - the comment "role" line (not stored; show time only);
  - #170 wants a click on the clock to open its target popover, but the
    clock is the old runtime chip, whose click sets the reading speed.
    This is noted on #170 and is for that issue, not this one.
- **Harness traps:**
  - `jsclick` doesn't blur;
  - `caret` has no offset;
  - `getComputedStyle` right after a class change reads the value from
    before the transition;
  - a phone test that widens the layout viewport makes every fixed
    element measure wrong;
  - a background driver holds its port.
  See SKILL.md "Gotchas".
