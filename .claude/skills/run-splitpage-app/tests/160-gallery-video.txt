# YouTube and Vimeo in a scene's gallery (#141, #168; 05v-video.js,
# 05e-gallery-overlay.js, shared/video-embed.js), against a FAKE host — no
# request in this suite leaves the page (the drivers set
# __splitpageNoRemote, and window.__videoTest stands in for the network):
#   * a pasted YouTube link's thumbnail is fetched once from i.ytimg.com,
#     its letterbox trimmed, kept as a blob (a ref in state, the bytes in
#     the registry), and lands in the PASTE'S undo entry: one Undo takes the
#     video and its picture, one redo brings both;
#   * Vimeo's comes through its oEmbed answer, from its image host;
#   * a failed fetch keeps the placeholder with no toast, and the dialog
#     offers "Retry thumbnail" (its own undo step);
#   * the dialog's player: click to play — no frame anywhere before the
#     button is pressed, never in the script; YouTube's no-cookie embed,
#     Vimeo's player with dnt=1; a sandboxed frame; a repaint for the same
#     item leaves it alone; picking another item or closing removes it;
#   * what cannot play says so and offers Open: YouTube from file://, a
#     player the page's policy refuses, a video file only named here;
#   * a video file dropped this session plays in a <video> from a blob: URL;
#   * other sites stay links; Settings ▸ Fetch video thumbnails off fetches
#     nothing; the desktop bridge is asked by host and id, never a URL;
#   * the policy's frame-src names exactly the two players.
