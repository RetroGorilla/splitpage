# Save As from a hosted document is a copy, not a save (#249, saveDoc in
# 14-export.js).
#
# A Save As from a server document deliberately writes a local file and keeps
# the page on the server document (56-one-home.txt pins the home). What it
# used to do on success was the rest of a save: it replaced the document's
# merge baseline with the copy — taking the copy's new id — and cleared the
# dirty flag and the pending autosave, though no PUT had happened. The editor
# then called unsaved edits saved, and a later merge measured against a
# baseline the server never accepted.
#
# Driven through the real saveDoc() twice: once by the handle path (the fake
# desktop backend, 20f-desktop.js, whose native Save dialog hands back a
# handle) and once by the download path (no backend and no
# showSaveFilePicker, the way Firefox is, with the file caught at
# URL.createObjectURL). For each, edits are typed into a hosted document with
# autosave held pending, and then:
#
#   * the hosted baseline, dirty flag, pending autosave and document id are
#     all exactly as they were — the first Save As and a second one that
#     forks a new id;
#   * the copy carries the edits and, for the fork, an id of its own;
#   * a local document still does what it always did: the copy becomes its
#     baseline, its id follows the fork and it reads clean.
#
# The hosted document is never saved to a server here, so the dirty flag can
# only be cleared by saveDoc's own success path — which is what is under test.
