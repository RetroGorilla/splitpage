# Import save-back is switched off (2026-10-30; this suite used to pin #251,
# "Save to <imported file>" must not call later edits up to date).
#
# An imported .txt now opens as a script with no file, like a new untitled
# one, and Splitpage never writes the imported file:
#
#   * with a writable handle or without one, there is no file chip, no Save
#     to file in the File menu, and the File menu's card says "Not saved yet";
#   * Save asks where to keep the script (the desktop bridge's Save dialog
#     stands in for the browser's), suggesting the script's name as .md, and
#     an edit typed while that dialog is open still leaves the script unsaved;
#   * the next Save writes the file it picked; the imported handle's
#     createWritable is never called.
# The save-back owner keeps its #251 cases as unit tests (I1-I3 in
# src/test/m4-matrix-files.test.mjs). Every `eval` is one physical line.

open
