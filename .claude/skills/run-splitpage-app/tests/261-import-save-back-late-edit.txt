# "Save to <imported file>" must not call later edits up to date (#251).
#
# saveBackToFile() (18-local-files.js) serialises the document, then awaits:
# the on-disk conflict check, the write, and for the download fallback the
# Save dialog. It used to set the import home's `dirty` flag false when it
# finished, whatever had been typed meanwhile, so a foreign .txt/.csv/.docx
# whose newest words were not in the file said "· up to date". It now clears
# the flag only if the import record, the document id and S.editSeq are all
# what they were when the bytes were built (the same test saveDoc applies to
# S.dirty), and moves the file's timestamp either way.
#
#   * in place: an edit made while the write is open leaves the chip on
#     "· unsaved changes", the bytes without the edit, and the timestamp
#     moved to the file's new one;
#   * the same save with nothing typed during it still says "· up to date";
#   * download (no handle, so the Save dialog of the desktop bridge stands
#     in for the browser's, which has no gap a person can type through): an
#     edit made while the dialog is open leaves it unsaved, and one with no
#     edit clears it.
# Every `eval` is one physical line.
