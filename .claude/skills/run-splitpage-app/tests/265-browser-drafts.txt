# Crash-safe drafts in the BROWSER for a script on a server (PR #233,
# 20g-drafts.js over 03d-drafts-idb.js). A guest co-editing through an
# invite link has no desktop app: until this their unsaved edits lived only
# in the open tab. Now the page keeps a draft of a server document's unsaved
# changes in this browser's IndexedDB — one per server and document id, the
# page's own writer id on it, never a token or a link's key — and the next
# time this browser opens that script (a reload, the link again, a new tab)
# it is merged through the desktop's own server path (armServerDraftResume
# → resumeServerDoc): both sides' edits kept, "Undo merge" armed, nothing
# saved on its own. A save that lands removes it. A link turned off keeps
# it; opened again after that, it comes back as an unsaved copy. No
# IndexedDB at all: nothing said, nothing thrown.
#
# The fetch emulator is 263's (health, join, me, the documents, the links
# API, presence) with one more switch, `failPut`: every PUT fails as if the
# connection had dropped. It is kept in localStorage so every `goto` (a real
# reload — a new tab, since sessionStorage is cleared first) reinstalls it
# in one line; the page's own boot probe finds no server, as in 263, and
# the real detection is run again with H.detect(). Before each `goto` the
# page's "unsaved changes" prompt is disarmed (BeforeUnloadEvent's
# preventDefault and returnValue made no-ops — a capturing listener that
# stops the app's own does not stop the prompt) — the tab going away with
# no prompt, which is the crash this is for. `wait` does not await a promise,
# so the store is read into `__rec` every 100ms and the waits read that.
# Every `eval` is one physical line.
