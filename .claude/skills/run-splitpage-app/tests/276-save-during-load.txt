# Save while the page is still loading (#276). Until the document has loaded
# S.state is null; the File menu's commands already said "Still loading…",
# but the header's Save, the writer's Save and the desktop app's native Save
# (D.runMenuCommand('save'), which clicks the header's Save) went straight to
# saveDoc(), which read S.state.docId and threw — an unhandled rejection, no
# word to the user. Each is now refused with the File menu's toast, shown as
# a warning, nothing is picked or written and the Save buttons are left as
# they were. The in-page
# Ctrl+S and Ctrl+Shift+S still refuse silently. The loading window is a few
# microtasks at boot, too short to click into, so the suite holds it open with
# __splitpageFormats.holdLoadingForTest(), which takes the document away and
# hands back a function that puts it back.
