# A review session (issue #30): the editor with the writing taken out of it.
#
# What is NOT here: whether the SERVER actually refuses a review client's
# document writes. That is the half that matters and it lives in
# `node tools/test-server.mjs` — this harness serves static files and cannot
# start server.js with an environment. Everything below is the other half:
# what the page does with the role the server hands it, driven through
# window.__hostedTest.setSession(), which says exactly what /api/health,
# /api/join and /api/me would have said and nothing more.
#
# The review key has to be in the address at LOAD time (the app reads the
# fragment once, on the way up), so it goes on `open` itself.

open /index.html#review=abc123def456
sleep 600
expect document.querySelectorAll('#rows .row').length == 2

# --- the review link's key is read, kept for this tab, and taken out of the URL
# Same rule as the launcher's key: a screenshot, a bookmark or a pasted link
# must not carry it, and it must not outlive the launch that minted it.
expect location.hash === ''
expect location.href.indexOf('review=') === -1
expect sessionStorage.getItem('splitpage-review-key') == abc123def456
expect localStorage.getItem('splitpage-review-key') === null
# nor on this device under Collaborate's map: that is only for a server

expect localStorage.getItem('splitpage-invites') === null
