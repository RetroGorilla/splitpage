# A reviewer's comments reach the server through the comment routes, never
# through PUT (#71, browser half; the server half is 8b813ad).
#
# The review token used to write by PUTting the whole script back and having
# the server prove, by diffing it against the stored one, that only a comment
# had moved. The server now refuses a review PUT outright, so the review
# client sends one comment or one reply at a time:
#   POST  api/docs/:id/comments              a comment (+ its anchor) or a reply
# and folds the stored copy the server answers with back into S.state and
# S.baseState (saveToServer's review branch, 13-hosted.js). It never sends
#   PATCH api/docs/:id/comments/:commentId   resolve / unresolve
# — reviewers never resolve or unresolve (the owner's decision: authorship
# cannot be established, so a reviewer's resolve would be of somebody else's
# comment), and the real server answers a reviewer's PATCH with 403
# reviewers-cannot-resolve, as the emulator below does.
#
# The harness serves static files and cannot start server.js, so `fetch` is
# replaced the way tests/54-server-conflict.txt and 55-pull-merge.txt replace
# it. This one is a small EMULATOR of the two routes rather than a queue of
# canned answers — it builds the stored comment itself on its own clock (the
# year 2030, so an adopted copy is unmistakable), bumps the rev, places the
# anchor only when unwrapping it gives back exactly the stored field, and
# answers a PUT with 403 review-only and a PATCH with 403
# reviewers-cannot-resolve, which is what the real one now does.
# What the real server checks is tools/test-server.mjs; what this pins is
# what the page does with the answers:
#
#   * NO PUT, ever, from a review session — not on posting, not from the
#     autosave timers the anchor's own markDirty arms, not on pressing Save;
#   * NO PATCH, ever, from a review session: a resolve found in its state
#     (only ever from an old stash) is not sent, and goes back to the
#     server's;
#   * the request is one comment, never the document;
#   * the server's copy is adopted, not kept alongside ours;
#   * THE REV. An answer at exactly (our rev + 1) is ours alone, so home.rev
#     takes it and the next heartbeat pulls NOTHING — a reviewer's own
#     comment must not come back round as a pull-merge of itself. An answer
#     further on means somebody else saved meanwhile: home.rev must NOT take
#     it (that would mark their save as seen and it would never arrive), and
#     the next beat pulls their change in;
#   * a stale anchor (anchored:false) takes the span back out of the scene on
#     screen and keeps the comment;
#   * a failed post stays and goes on the next Save, with the same ids (the
#     server's idempotent retry); a refused one stays on screen and is not
#     re-sent;
#   * an editor on the same document still saves with PUT.
