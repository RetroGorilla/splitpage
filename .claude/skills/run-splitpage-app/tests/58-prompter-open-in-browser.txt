# The teleprompter's "Open in browser" (issue #86), both ends of it that a
# browser can reach.
#
# THE BROWSER END. The desktop shell opens one of two addresses in the
# default browser (desktop/main.js section 9b):
#   ?teleprompter=1#script=<64 hex>   served by the desktop's own loopback
#                                     listener (desktop/prompter-share.js)
#   ?doc=<id>&teleprompter=1          served by its document server
# This harness's static server cannot answer prompter-script/<token> the way
# that listener does, so the success path is driven through
# window.__prompterTest.launchFromScript — the same function a real load
# runs — with fetch stubbed. The address parsing is driven for real, by
# loading those addresses: they fail to find a script (the harness has none
# to give), which is the expired-link path, and that is asserted too.
#
# THE DESKTOP END. The renderer's half of the button — save first when that
# needs no dialog, refuse and explain when it would, never name a URL — runs
# under the in-memory fake desktop backend (20f-desktop.js), like
# 21-desktop-shim.txt. The main-process half (what URL, what bytes, the
# listener itself) is desktop/test/smoke.mjs's "teleprompter: open in
# browser" groups and desktop/test/prompter-share.test.mjs.
#
# Follow My Voice itself cannot be driven here or anywhere headless — it
# needs a real microphone.
#
# Every `eval` is one physical line (the driver splits on newlines).

# itself: the first-run wizard is for someone arriving at the app, and this
# tab arrived at a script.
