# The header's condense/expand as one movement (#52, 20i-topbar.js + app.css)
# and the document keeping step with a side panel that is leaving as well as
# arriving (#53, the #root rules in app.css).
#
# Animation cannot be judged headless — whether the movement READS as one
# thing is a human's call. Its mechanics can be, and that is what this suite
# is: the layout lands in one frame, a transform puts the pixels back, a
# reversal cancels what was running instead of layering a second transform
# over it, and the transitions are the ones the two issues asked for.
#
# Every mid-movement reading is taken in ONE eval into a snapshot object and
# asserted against afterwards. A run of `expect`s straight against the live
# page would each cost a driver round trip, and eight of them after a 60ms
# sleep can walk past the 180ms the movement lasts on a slow machine — the
# assertions would then be timing the harness rather than the app.
#
# Two things about how the reduced-motion half is driven, because neither is
# obvious:
#
# - The driver's `viewport` sets device metrics, not media features, so there
#   is no way to ask this browser for prefers-reduced-motion: reduce. The JS
#   half is driven instead by replacing window.matchMedia — 20i-topbar.js
#   calls it at decision time rather than caching the answer, so a stub
#   really does take the no-motion path, and the case below asserts the class
#   still flips with nothing animating and nothing taken out of flow.
# - The CSS half is read off the shipped stylesheet rather than measured: the
#   @media (prefers-reduced-motion: reduce) blocks are found in
#   document.styleSheets and their text asserted. That proves the rules ship
#   and say what they must; it does not prove the browser applies them, which
#   is the browser's job and not this app's.
#
# Everything here is one line per eval — the driver reads the script line by
# line. viewport is set once at the top (>=1100px, where #root's padding-right
# tracks the open panel) and never changed again, and there is no `goto` after
# the first; see the SKILL's gotchas on both aborting the CDP socket.
