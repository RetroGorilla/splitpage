# Google Drive in the desktop app (issue #10), the renderer's half.
#
# On desktop the MAIN process signs in to Google through a loopback OAuth
# redirect and makes every Drive request (desktop/google-drive.js, main.js
# § 9c). The page gets six bridge calls: driveStatus / driveSignIn /
# driveSignOut with no argument, and driveList / driveDownload / driveUpload
# with a Drive id or an upload request. It never holds a token, never names
# a URL, and has no API key or Client ID form. There is no Electron shell
# here, so window.__desktopTest swaps in its fake backend with the drive
# members (makeFakeBackend({drive:true}), 20f-desktop.js) and drives the
# real modal code in 13-hosted.js against it. The OAuth flow itself, the
# token storage and the requests to Google are desktop/test/smoke.mjs's
# "google drive" groups (against a fake Google) and
# desktop/test/google-drive.test.mjs.
#
# Every `eval` is one physical line (the driver splits on newlines).
