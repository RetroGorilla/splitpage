# Images inside HTML out of the document state (#82 P6). A comment's
# or a reply's picture is stored as
#   <img class="comment-img" data-blob="<sha>" data-w data-h data-mime>
# with NO src: the sanitiser (04-richtext.js) interns an inline data: image
# into that form, and the hydrator (02c-blobs.js) gives the <img> a blob:
# URL on screen only. What this pins, the way a user does it:
#   * a picture attached in the comment composer: the stored body names it
#     by sha, it is in IndexedDB, the card shows it from a blob: URL;
#   * a picture pasted as HTML into a reply: the same; pasted into a
#     scene's cell it stays out of the words (#85 design D7) and goes
#     into the scene's gallery (#135);
#   * a .splitpage save carries every one of them inline (src="data:…"),
#     and opening that file gives the stored form back;
#   * the crash/sign-in stash carries them across a real reload as refs,
#     and they render again out of IndexedDB;
#   * an old document whose comment, reply and cell pictures are inline
#     data: URIs opens content-addressed, the cell's moved into a comment.
# The sanitiser's own rules (idempotent, bad sha, never SVG) are
# src/test/html-images.test.mjs. Every `eval` is one physical line.
