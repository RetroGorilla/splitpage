# Formatting and line breaks through the document model (#85, design §5;
# src/js/05-render.js toggleCellFormat / insertLineBreak, over
# src/js/05b-cell-edit.js editCell).
#
# In a script cell, B/I/U/S, highlight, a link and Enter are edits of the
# cell's model, not execCommand: state gets the canonical markup
# (<strong>, <mark>, <a target rel>) at once rather than after a blur, the
# toggle is decided by the model (every character already has it -> off),
# the selection survives the repaint, and each is one undo entry. With
# nothing selected, B/I/U applies to what is typed next. A cell still
# holding a picture (none does since design D7) is left alone: nothing
# edits it behind the model's back. A comment composer is not a document
# cell but goes through the model too (05d-draft-edit.js; its own suite is
# 81-draft-edit.txt). The pure core is src/test/doc-model.test.mjs ("the
# editor's formatting edits").
#
# Every `eval` is one physical line (the driver splits on newlines).
