# The Production and Gear panels in a review session (#30;
# src/js/08-production-panels.js, 20-teleprompter.js wireTagEntityContainer,
# src/bootstrap/wiring/production.ts): the breakdown to read, not to change.
#
# Their clicks were already refused by the click guard (src/features/review/click-gate.ts
# REVIEW_SAFE_ACTIONS), but their form fields were not: a reviewer could
# change a card's owner, type into its notes, and Ctrl+click (or long-press)
# a selection and use the bulk bar's selects. The server keeps none of it,
# so each edit looked as if it had worked and was then lost. Now:
#
#   * an open card's status and owner are drawn disabled and its notes
#     read-only (the values still readable); + Person, Rename and
#     Remove/Delete are not drawn; the head's status pill is a label; the
#     Person grouping has no "remove from crew" ×;
#   * no selection: Ctrl/Shift+click opens the card and selects nothing, a
#     long-press selects nothing, and the bulk bar is never drawn;
#   * a control forced back into the page is refused by its handler (change,
#     input, Enter, the click guard), with the "Viewing only" toast, and the
#     breakdown is left as it was — the guard, not the CSS, and not the body
#     class either;
#   * the two exports, the Production panel's CSV and the Gear panel's
#     Packing list, still make their files and change nothing;
#   * the same document as an editor gets every control back.
# Like 43-review-mode.txt, the role comes from window.__hostedTest.setSession
# (the harness cannot start server.js). Every `eval` is one physical line.
