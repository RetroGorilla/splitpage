# Stage 0: DocumentSession and its callers

This audit classifies the current session contracts and the write paths that the Stage 1 shared-session experiments must replace or isolate.

Audited baseline: `0ca1929177ffc84bced412ad2be3aa99690761d0`.

Scope follows [plan sections 3, 4 and 12](../../COLLABORATION-PLAN.md), with terminology from [the glossary](../../GLOSSARY.md). This is an inventory, not the Stage 2 caller migration. Tags use the corrected lane brief: T01 covers all three buffer mechanisms; T20 is concurrent nested marks, T21 selective mark/comment undo, T22 journal receipts, T23 reconnect coverage and T24 the writable-tab lock.

## Table 1: contracts and callers

Counts distinguish **boundary sites** (calls or function references supplied to ports) from **consumer modules** (distinct source files invoking that contract through the port). Mechanical forwarding inside `src/bootstrap/wiring/session-owner.ts` `session` and test-only hooks are excluded. A named port assignment counts once, rather than once per feature receiving the object. Counts describe source, not runtime invocations; a loop can install several listeners. Paths in the caller column are relative to `src/` unless fully qualified. `Undo.*` below means `src/application/editing/undo/undo.ts` `Undo`.

### Count verification and constraints for the slice

The plan's **three `held()` call sites outside wiring are correct as a literal `.held()` search**, excluding tests: `src/application/editing/undo/undo.ts` `replayUnwired` and its private `held`; `src/application/production/broll-records.ts` `reconcile`. That is three sites in two modules, not three independent writers. Aliasing widens the exposure: `src/application/session/session-merge.ts` `sessionMergePorts.current` calls the captured `ports.session.held` as `heldDocument()`, and `src/application/save/project-files.ts` `formats.state` calls `ports.heldDocument()`. Table 2 includes those and the wiring reads rather than treating the literal count as a containment proof.

The plan's **one app caller of `noteEdit` is correct for the unknown-extent edit bridge**: `src/features/imports/imports.ts` `confirmImport` calls local `noteSessionEdit`, supplied as `noteEdit: noteSessionEdit` by `src/bootstrap/wiring/imports.ts` `mountImportDialogFeature`. It is only the new-document import branch; append/replace in the current document uses `importRowsCommand`. `src/bootstrap/wiring/desktop.ts` `testHooks.markDirtyForTest` is an additional test-only bridge call. `Undo.noteEdit` is a different API used for recording all session commands.

Ordinary editing still overwrites plain projected values: `src/features/writer/flow-surface.ts` `syncBeatEl` decodes whole-beat DOM; `src/application/editing/cell-editing.ts` `sync` decodes whole-cell DOM; `src/application/commands/flow.ts` `flowCommand` replaces the row list from `FlowOutcome`. Dispatch alone is not an intent stream. For T01–T09/T20/SLICE these bindings must retain the matching epoch and editor base before reconciliation; Table 2 intentionally covers the five hazardous API classes rather than duplicating the command inventory.

Standalone undo behaviors to compare explicitly in T04/T12/T21/SLICE: `src/application/editing/undo/history.ts` `COALESCE_MS` is 1,000 ms and `MAX_ENTRIES` is 200; history parks redo and can return it when typing coalesces back to its start; `compositionMark` / `dropEmptySince` manage composition groups; `src/application/save/file-saving.ts` `writeDoc` holds undo/redo after bundle draining until the Save As write settles. That hold can last while the write is stuck, but applies to its captured epoch. Shared differences remain experiment outcomes, not implied compatibility promises.

Plan section 3 fixes three remote requirements: no undo record, no attribution stamp and no save trigger. None of the existing edit/replay/amend effect passes satisfies that contract. A shared remote transaction still needs the same precise `SessionChange` publication and projection invalidation, while generation/remote-version semantics are explicit in the stale-base experiment. `stamp` is not a transaction kind and does not publish `SessionChange`; its separate `onStamped` route already matters to painting. For T13/T15/T22/T23, neither local generation, `rev` nor the save coordinator's change count proves server durability coverage.

Capability detail for T11/T13/T19/SLICE: `src/application/commands/cell-text.ts` `cellTextCommand` declares `needs: nothing`, checks capability after missing-row/no-op tests, and still permits an anchor-only change when edits are denied. In `src/application/commands/comments.ts`, `addCommentCommand`, `addReplyCommand` and `unwrapCommentAnchorCommand` also declare `needs: nothing` and never call `capability.edit()`; unwrap can rewrite cell HTML. `replay`, `amend`, `stamp`, adoption and `noteEdit` have no session-level capability check. The present all-allow port therefore cannot itself prove revocation. The shared refusal experiment must exercise these reached bindings and the retained buffer when access changes; it must not turn refusal into lost composed text.
