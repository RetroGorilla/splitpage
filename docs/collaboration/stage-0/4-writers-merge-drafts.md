# Stage 0: automatic writers, merge and drafts

This audit identifies standalone persistence and replacement entry points that the Stage 1 shared-session experiments must isolate.

Baseline commit: `0ca1929177ffc84bced412ad2be3aa99690761d0`.

## Reading the inventory

The [collaboration plan](../../COLLABORATION-PLAN.md) is authoritative for shared-mode rules; the entries below describe current code. `SLICE` means the throwaway two-replica real-editor slice; `STORE` means local replica storage/hydration; numbered tags use the corrected lane brief, including `T24` (second-tab refusal and crash release). `S2` rows deliberately contain only a name and location. No production changes are proposed here.

Rule references in the tables cite these plan sentences:

| Rule | Plan sentence |
| --- | --- |
| P1 | [Section 3](../../COLLABORATION-PLAN.md#3-repository-integration): “A remote change records no undo entry, stamps no attribution and triggers no save.” |
| P2 | [Section 3](../../COLLABORATION-PLAN.md#3-repository-integration): “In shared mode, disable the local three-way merge, conflict-stash application and independent drafts of the live document.” “The replica is the live recovery source.” |
| P3 | [Section 3](../../COLLABORATION-PLAN.md#3-repository-integration): “Existing history snapshots can remain explicit recovery checkpoints; restoring one must not overwrite the authoritative replica.” “Keep these paths unchanged in standalone mode.” |

| P5 | [Section 3](../../COLLABORATION-PLAN.md#3-repository-integration): “Desktop tabs know only `file` and `blank` sources, so a shared instance needs its own tab source for restore, duplicate detection, close and quit.” |

The normal entry is not an isolated test host. `src/bootstrap/main.ts` `mountAndStart` unconditionally mounts history, file-saving listeners, local files, merge review, desktop, drafts, app-data and new-tab features; `src/bootstrap/wiring.ts` `wireApp` also starts saves, destinations, transitions, merge and recovery. The smallest common Stage 1 boundary is a throwaway composition entry which omits these standalone entry points and supplies the real editor with shared-session ports. Rows name additional guards needed if an existing mount is reused. These are prototype requirements, not a Stage 2 disable design.

## Registry coverage and safe prototype identity

Detaching at `createSaveDestinations` is necessary but not sufficient. It covers new queued file saves, autosaves, forced writes, Save As and the dormant import writer. It does not cover already-selected jobs, draft capture/discard/restore, stash application, history writes/restore, last-file resume, inbound opens, identity reassignment, shell restoration/recents, explicit exports, blob persistence or attachment jobs. Those have independent entry points above.

History is the durable docId-addressed store: W34–W36 and W46–W47 read/write/copy/export/import its buckets; pending snapshot entries and eviction holds also use docId. Browser/desktop claims W38–W39 compare docId, but index claims by channel/page or webContents and require file homes. Drafts W28–W33 carry docId in header/body and compare identity on file restore, but their storage/hold/discard address is tabId/sequence. A fresh instance docId isolates history, not drafts, global stash, last handle, Older history, recents or tab restore. File save queues use desktop file id or browser handle identity, not docId; image stores use hashes.

Use one newly minted valid docId per instance, shared by that instance's simulated replicas, never the source file's id. Use fresh ids for exported standalone copies; current copy exporters omit the id and file entry derives it from content, so identical copies can still share an id (W54). Give separate simulated devices isolated browser profiles/origins or desktop userData; use the same-device setup deliberately for T24. Do not use different docIds per client to sidestep the instance lock experiment.
