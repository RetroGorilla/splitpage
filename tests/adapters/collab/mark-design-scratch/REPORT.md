## Literal histories and the lost event

The original four-command history starts with plain `abcd`. A marks `bc`; B marks `c`; A marks `d`; B deletes `abc`. The last character was explicitly marked and nobody removed its mark, so the hand-written result is marked `d`.

The original three-command history starts with `bc` already marked and known to both writers. A deletes `c`, then `b`; B types explicitly plain `X` between the original `b` and `c`. The hand-written result is plain `aXd`. In sequential schedules B's saved anchor resolves into the collapsed gap; its explicit plain mark set is still empty.

The additional fatal history starts with plain `abcd`. A and B are disconnected:

1. A adds italic to `bc`, under a new immutable key A1.
2. A deletes `bc`; it never issues a mark removal.
3. B, which has never seen A1, inserts plain `X` between the original `b` and `c`.

The surviving character `X` is strictly inside A1's original range. The expected result is `a` + italic `X` + `d`, consistent with Stage 1 T21's concurrent interior insertion rule. Design 1 reads plain `aXd` on both writers and the late joiner, in ordinary, reversed and duplicated delivery. Design 2 reads italic `X` on all copies. The same failure reproduces for all ten kinds; tag and link additions are not special cases.

The source explains the loss without a private flag: `node_modules/yjs/src/types/YText.js`, `deleteText` (lines 539–560), calls `cleanupFormattingGap` during the deletion transaction. The gap walker (lines 366–415) retains the last format per key and deletes earlier/redundant formats. Once `bc` is deleted, the positive A1 marker and its closing null marker are redundant in that copy's current gap. They are deleted before B's concurrent text arrives. Delivering those deletes correctly makes every copy agree on the wrong mark set. Changing the cleanup origin cannot recover A1.

The first expanded attribute-generator failure (seed 1, two writers, D1) adds an unwanted bold mark. Preserving that direction of failure reduces it in 35 trials to two commands: B types plain `X` just before the original `b` in `abcd`, and disconnected A makes the original `bc` bold. Under the tight anchored range rule, the expected result is plain `aX`, bold `bc`, plain `d`. Native attributes also make `X` bold. This boundary rule is stated as an assumption below. The interior-deletion defect above does not depend on that boundary choice. Both minimal traces are committed as JSON; `reduce.ts` can replay and minimize them independently.

## What the generator checks

`model.ts` receives command inputs and delivery knowledge, not adapter mark readings, native deltas or the record validator. It keeps symbolic character identities, deletion sets, independent addition/removal sets and immutable insertion provenance. Initial characters are undeleted fences; generated insertions have distinct predefined gaps between fences. This fixes text ordering independently of Yjs, while mark ranges, removals and deletions still overlap across writers. Separate literal tests cover concurrent same-gap ordering with two and three writers. Character ids are bound to native ids only when created, through `tests/collab/checker.ts`'s identity model.

The independent reader applies every addition covering a surviving character, except additions named by an observed removal covering that character or by that character's birth suppression. It unions surviving additions, retaining kind, identified-mark id and payload. An inserted explicit/inherited mark is a fresh addition restricted to the inserted identity range. No mark can appear without a corresponding command. A negative control omits an addition on every replica: the replicas agree, and the independent model still rejects the result.

The schedules use the same queue rules as `tests/collab/delivery.ts`, extended to name a fourth read-only copy for the three-writer runs. D1 holds all updates until the end. D2 settles after every command. D3 selectively delivers B's pending updates before A's next command, without delivering A's pending updates. `dup` delivers every message twice. `rev` reverses each pending batch. `late-C` settles halfway, creates a new copy, then delivers subsequent edits to it. Every other schedule creates its late joiner at the end. D2 has 100 or 150 sequential settles; D3's selective points and `late-C`'s post-join deliveries are asserted. Checkpoints compare every writer with the independent expected state and a newly encoded-state reload.

Command fingerprints include causal knowledge and selected identities. D1, dup and rev have identical command histories: 96 cross-schedule comparisons. D2/D3/late-C may change what a writer has observed or selected; equality across those different commands would be an invalid requirement, so each is checked against its own command-list result.

The rejected attribute generator remains executable as `node --test tests/adapters/collab/mark-design-scratch/rejected-attributes.ts`. It intentionally exits 1: 30 reduced lost-mark cases, the outside-edge case, and the first generator violation. It is not a product test disabled to obtain a passing gate; it is separately named scratch evidence for a rejected candidate. No existing assertion was changed. The normal scratch `.test.ts` files test the supported record candidate and both candidates' original literal/typing cases.

## Cost methodology and retained state

`measure.ts` measures one eight-UTF-16-unit segment on this machine, with client id `0x1234abcd` so the encoding includes a realistic five-byte client id. Add-only repeatedly adds italic over all eight units under fresh operation ids. Mixed commands repeat add over `[0,8)`, remove over `[1,7)`, and explicitly plain insertion at offset 4; a following text deletion keeps the segment at eight units. Text deletions do not count as mark commands or create records. Both designs therefore write exactly N mark events. Record storage retains all N records; the mixed reader currently resolves 8 / 68 / 668 nonempty events at N = 10 / 100 / 1,000. Attributes can disappear after their characters are deleted; that is part of the correctness problem, not a safe record-compaction strategy.

Each timing has five warmups, then fifteen samples of five reads; the reported value is the median per read. Encoded bytes include the shared fixture's complete document state, not just its mark map. Raw output records p95 and a checksum. Record births name observed active additions that actually cover the new characters, rather than every addition anywhere in the segment. This avoids unnecessary references to already suppressed additions in the measured mix. Dense histories of overlapping live additions can still make observed-id lists large; causal compaction is not implemented or assumed safe here.

## Assumed, for the product review

An addition not observed by a concurrent removal survives. Explicit plain insertion excludes additions the writer observed on that inserted text; it does not veto an unseen concurrent addition whose range includes the new character. That is the same observed-addition rule, not a global plain override.

For range edges the prototype uses tight start/end anchors: insertions outside the first/last selected character are excluded, while strictly interior insertions are included. Settled typing preserves today's flow-provided explicit formatting: ordinary formatting inherits from the left except at offset zero, directions inherit only between two direction characters, and identified marks do not inherit. Cues follow today's cue-line normalization. The reader stores raw mark membership; later projection still applies the existing cue/tag/link presentation rules.

Multiple surviving payloads for one identified mark id are retained as a set. The final presentation rule for concurrent different payloads under the same id is not determined by the records examined; the projection must not silently choose by map iteration. No tag/comment/link registry or comment-body record is created by these prototypes.

The heading-surrogate decision is recorded for eventual C: shared heading base references clamp to pair boundaries, like narration, while standalone is unchanged. Flow agreement will contain exactly one declared limit for an offset inside a heading surrogate pair. This scratch comparison does not implement C or broaden that limit.

## Recommendation

B should implement the chosen storage form, deterministic hydration and one shared validator/reader helper before C writes marks. The existing anchor target limitation for visual/title text must be addressed explicitly. No production choice has been implemented by this scratch branch.

Choose Design 2. Design 1's immutable keys and suppression records cannot prevent Yjs from discarding the only stored positive event when its current text vanishes. Preserving those events in a separate anchored registry would make it Design 2. Design 2 passed the independent character rule and has no text formatting items for cleanup to reinterpret. Its measured storage cost is higher. Read cost depends on the history; segment-local indexing and caching are future implementation work, not evidence substituted for correctness.
